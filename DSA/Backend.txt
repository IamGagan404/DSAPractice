They are lazy in this sense. .explain() is used for query N+1 problems is when django crates query but additional data from other table is also required hence djnago creates query for each of them(when lopped over) resulting in larger number of queries than required. FASTAPI

=> dependency injection
lets you declare reusable logic(db session auth etc) as separate function and fastapi automatically calls
it before the endpoint. Everything before yield get called before endpoint and after yield after result is generated. 

def get_db():
    db = session()
        try:
            yield db
        finally:
            db.close()

@app.get('/products')
def get_products(db : Session = Depends(get_db))
    products = db.query()
    return products

=> Explain the difference between async def and regular def endpoints in FastAPI, and what happens if you accidentally put blocking (synchronous) code — like a blocking DB call or time.sleep() — inside an async def endpoint.

async functions run on main event loop and await for non blocking ops and give control backt ot main event loop. sync function are run separtely in threadpool run_in_threadpool() hence dont block main event loop
if aysnc fun uses blocking func then it will block main event loop.
